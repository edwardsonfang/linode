# Linode HLS 资源同步工具（Java 单文件交付）

交付源文件：`LinodeHlsSync.java`。它包含完整实现，不依赖本项目的其他类或 Python。

输入一个 `.m3u8` URL，程序递归查找并下载主/子播放列表、音视频分片、初始化文件和适用的密钥文件，改写播放列表中的引用，然后上传到 Linode Object Storage。每个对象都通过已认证的 GET 回读核对 SHA-256 和 Content-Type。**只有全部成功才返回 JSON 格式的 Linode URL 列表**。

## 1. 环境与依赖

需要 JDK 17 或更新版本，以及以下 AWS SDK for Java v2 依赖（含传递依赖）：

```xml
<dependencies>
  <dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>s3</artifactId>
    <version>2.30.38</version>
  </dependency>
  <dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>url-connection-client</artifactId>
    <version>2.30.38</version>
  </dependency>
</dependencies>
```

使用 Maven 下载运行依赖至 `lib` 目录，或由现有项目的 Maven/Gradle 管理依赖。完整的最小依赖配置见 `客户依赖配置.xml`：

```sh
mvn -f 客户依赖配置.xml dependency:copy-dependencies -DincludeScope=runtime -DoutputDirectory=lib
javac -encoding UTF-8 -cp 'lib/*' LinodeHlsSync.java
```

## 2. 配置

通过运行环境安全注入以下密钥，**不要将真实密钥写入源码、文档或版本库**：

- `LINODE_ACCESS_KEY`：对象存储 Access Key。
- `LINODE_SECRET_KEY`：对象存储 Secret Key。

以下均为占位示例。请替换为自己的实际桶、区域与端点：

```sh
export LINODE_ENDPOINT='https://region-id.linodeobjects.com'
export LINODE_REGION='region-id'
export LINODE_BUCKET='example-bucket'
```

区域签名配置应与目标端点匹配。无需 Linode 账户管理 API Token。密钥需要具备目标对象的写入和读取权限，读取权限用于上传后的完整性验证。

## 3. 执行

```sh
java -cp '.:lib/*' LinodeHlsSync \
  'https://media.example.invalid/video/master.m3u8' \
  'customer-hls-001' \
  --work-dir './download-customer-hls-001' \
  > result.json
```

Windows 的运行时 classpath 使用 `.;lib/*`。工作目录必须尚不存在；每次使用新的对象前缀，避免覆盖现有数据。进度输出到标准错误，不会混入标准输出 JSON。

程序不会预置任何客户源站域名。若源站要求 Referer，可显式指定；User-Agent 默认是 Mozilla/5.0：

```sh
--referer 'https://player.example.invalid/' --user-agent 'Mozilla/5.0'
```

若依赖或重定向使用另一个 CDN 域名，使用 `--allow-host 域名` 显式允许；可重复提供。云环境的网络允许列表也必须放行实际源站和目标端点。程序不会关闭 HTTPS 证书校验。

## 4. 返回结果

以下为结构示例，文件名、前缀和对象数量以实际输出为准：

```json
{
  "playlistUrl": "https://example-bucket.region-id.linodeobjects.com/customer-hls-001/index.m3u8",
  "bucket": "example-bucket",
  "prefix": "customer-hls-001",
  "verifiedObjectCount": 37,
  "objects": [
    {
      "key": "customer-hls-001/index.m3u8",
      "url": "https://example-bucket.region-id.linodeobjects.com/customer-hls-001/index.m3u8"
    }
  ]
}
```

`playlistUrl` 是入口播放列表；实际 `objects` 列出所有上传对象。播放列表内部使用相对引用，与返回域名及前缀配合使用。

可设置 `LINODE_PUBLIC_BASE_URL` 自定义返回地址的基础部分，例如自有 CDN 域名或 `https://region-id.linodeobjects.com/example-bucket`。该设置只影响返回 URL，不会自动配置 CDN。

返回的 URL **不带签名**。要允许匿名播放，必须为相应对象配置公开读取权限，并为跨域播放器配置 CORS。仅设置桶 ACL 为公共 READ，并不保证对象允许匿名 `GetObject`。程序不会修改 ACL、桶策略或 CORS。对于私有内容，应使用认证网关或覆盖全部播放列表与分片请求的授权方案。

## 5. 失败行为与范围

- 源站下载不完整时，不开始上传。
- 任一上传、GET 回读或校验失败时，退出码为 1，不返回成功 URL JSON。
- 失败后保留工作目录；目标桶可能残留部分文件。程序不会自动删除对象。
- 成功时退出码为 0，工作目录同时保存 `result.json`。
- 源站临时网络错误及429/5xx最多尝试3次；遵守最长60秒的Retry-After，较长等待直接退出提示稍后重跑。上传使用SDK默认重试策略。
- 默认最多 10,000 个资源、10 GiB 下载量；可通过 `HLS_MAX_FILES`、`HLS_MAX_BYTES` 调整。单个播放列表限制为 16 MiB，最大嵌套深度为 64。
- 支持静态点播和常见 URI 引用；不转码、不合并媒体、不解密。
- 不支持直播、LL-HLS、HLS 变量替换、内容引导、DRM许可证获取、多段上传、断点续传。AES-128 identity 密钥仅按文件复制。
- 不在未经授权的情况下公开客户视频或密钥文件。

## 6. 验证依据

独立源文件已通过六项本地集成测试：递归下载、URL去重、引用改写、S3上传和GET回读、URL结果输出，以及下载失败、上传失败、回读不一致、直播播放列表拒绝和源站临时503重试场景。历史实站验证已完成完整 HLS 资源的 Linode 上传与回读校验；真实地址、媒体和运行记录不包含在公开仓库中。
